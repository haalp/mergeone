One decision per merge,
at swarm scale.

When most of your commits are written by agents, the merge queue is the bottleneck. mergeone replaces its one slow question with five fast, typed, calibrated ones per pull request, and turns them into a verdict through a policy file you own.

Typed, not prose

The model returns probabilities, not a review comment. A rule like weakens_tests >= 0.6 → block is one line of YAML.

Calibrated before rules run

0.6 means sixty percent. Isotonic maps fitted on labelled history ship with the binary; raw ECE 0.17 becomes 0.03.

Fail closed, log everything

Model down? The PR holds for a human. Every verdict is stored with its exact input, because a System One model gives no rationale.

Landing plans, not serialisation

Hundreds of open agent PRs become waves of non-conflicting changes that land in parallel; one typed question catches semantic conflicts files cannot.

Built on a benchmark that says what does not work.

gatebench is pre-registered: hypotheses and thresholds were committed before any model ran, and results are published whichever way they fall. 40,000 Kubernetes merges, four systems, two runs.

Run 1 · negative result
Reverts cannot be predicted from a diff.

Rules, gradient boosting, Claude Haiku 5.5 and Jev all score PR-AUC ≈ 0.010 against a 0.0075 base rate. Pre-merge state does not contain that signal. Nobody else publishes this.

Run 2 · positive result
Typed triage is solvable, fast and cheap.

Behaviour change, weakened tests, concurrency risk and needs-human each reach ROC-AUC 0.87–0.96 with calibrated ECE under 0.05, in one request per PR. Jev meets the pre-registered bar on 5/5 questions at 347 ms and $0.074 per thousand.

The agent asks before it merges.

mergeone is an MCP server. Register it once, add one line to your agent's instructions, and every merge goes through the gate instead of around it. The same calls exist over HTTP for everything else.

# register
claude mcp add mergeone -- mergeone mcp --policy .mergeone.yaml

# CLAUDE.md
Before merging, call gate_decide. Merge only on "pass".

# response
{ "verdict": "hold", "route": "human",
  "rule": "message-mismatch",
  "probs": { "message_matches_diff": 0.31, … } }
